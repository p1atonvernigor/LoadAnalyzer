# Анализ нагрузки ПК — правила для Claude

Отдельное приложение для Windows: показывает, что грузит ПК, находит скачки и
объясняет их через Google Gemini. Родилось из модуля «Аналитика нагрузки» проекта
AITG, но живёт самостоятельно (на ПК владельца — `D:\AITG\LoadAnalyzer`). Владелец пишет по-русски,
объяснять простыми словами, без жаргона.

## Запуск и проверка

- Запуск: `run.bat` (ставит `psutil` из `requirements.txt`, затем `py -3 -m analyzer`).
  Окно: Edge `--app=http://localhost:8777`, иначе браузер по умолчанию.
- Тесты: `py -m unittest discover -s tests` (89 тестов, все зелёные). Интернета,
  настоящих датчиков, psutil и ключа Gemini не требуют — всё подменяется.
- Любая правка кода заканчивается прогоном тестов; исправленная ошибка получает свой тест.
- После правок приложение перезапустить (закрыть консоль, снова `run.bat`); окно само
  перезагружается по метке `boot`.
- `run.bat` обязательно с переводами строк Windows (CRLF): с LF cmd может разбирать файл неправильно (есть тест).
- Порт окна 8777; занят чужой программой или закрыт Windows — `start_server` берёт следующий (до 10), на порту уже наше приложение — просто открывает окно.
- Python 3.13, только стандартная библиотека + `psutil`. Новых зависимостей без нужды
  не добавлять.

## Чем отличается от AITG

Здесь **нет**: Telegram-бота, LM Studio и локальной модели, режимов (normal/game/…),
хаба модулей, сортировщика, уведомлений и отчётов картинкой, автовыключения и
выгрузки модели по перегреву. Только анализ нагрузки и показ в окне.

Вместо локальной модели — **Gemini по HTTP** (`analyzer/services/gemini.py`). 26.10 у Google была перегрузка Flash (503 «high demand» и зависания до тайм-аута): `ask_full` повторяет попытку 3 раза (паузы 2 и 5 с, одна попытка до 45 с, всё вместе до `gemini_timeout_seconds` = 180), потом пробует запасную модель `gemini_fallback_model` (gemini-flash-lite-latest; ей нельзя отключить «размышления», она медленнее ~30 с). Ключ/404/429 не повторяются. К Gemini — через системный прокси.
Вместо журнала в памяти на 30 минут — журнал на диске на 12 часов (настраивается).

## Архитектура

- `analyzer/app.py` — класс `App` (настройки, ключ, журнал событий, монитор) и `main()`:
  поднимает сервер и `Monitor`, открывает окно. Если порт занят — только открыть окно.
  `open_page("key"|"lhm")` открывает в браузере страницу ключа Gemini или загрузки
  LibreHardwareMonitor (только эти две, остальное отклоняется).
- `analyzer/monitor.py` — `Monitor`: поток замеров каждые `poll_seconds`, журнал через
  `History`, поиск скачков/нагрева/износа (`spikes`), вопрос к Gemini, данные для окна
  (`state()`), определение игры (`game_name()`), подсказка про LibreHardwareMonitor
  (`lhm_hint()`). Датчики подменяемы (поля `read_gpu`, `read_ram`, `apps`, `gpu_apps`,
  `read_power`, `read_lhm`, `ask_model`), `sync=True` в тестах выполняет вопрос сразу.
- `analyzer/core/`:
  - `settings.py` — `DEFAULTS` + `config/settings.json` (только отличия). `set()`
    проверяет тип и пределы (`LIMITS`), текстовые — `TEXT_KEYS`, переключатели — `BOOL_KEYS`.
  - `secrets.py` — ключ Gemini в `data/secrets.json`. Наружу только `has_key()`; ключ
    никогда не печатается и не отдаётся в окно.
  - `history.py` — `History`: замеры в `deque` + файл `data/history.jsonl` (одна строка =
    один замер). Хранит `history_hours` часов, файл подрезается при запуске и раз в 10 мин.
    Битые строки и замеры «из будущего» при загрузке пропускаются.
  - `logbook.py` — журнал событий (последние записи в памяти + файл).
  - `storage.py` — атомарная запись JSON.
- `analyzer/services/` (общие с AITG по происхождению, но скопированы сюда):
  - `procs.py` — программы: CPU/ОЗУ через psutil, видеокарта по программам через счётчики
    Windows (pdh.dll, английские имена). Нет данных — None + `.reason`.
  - `load.py` — общая загрузка CPU (GetSystemTimes), видеокарты и памяти.
  - `sensors.py` — температуры: nvidia-smi (GPU), LibreHardwareMonitor (CPU, порт 8085),
    RAM через GlobalMemoryStatusEx. Всё возвращает данные или None, не бросает.
  - `gpu_power.py` — мощность/напряжение/частота/вентилятор/температура видеокарты.
  - `spikes.py` — считает скачки (CPU +25/≥40%, GPU +30/≥50%, ОЗУ +8%, VRAM +800 МБ),
    нагрев (+8° от «как было», ≥55°), выжимку для модели (`digest`), износ (`wear`),
    разбор ответа (`parse_answer`). Видеопамяти уделяется больше всего внимания (везде
    первой). `system_prompt(minutes)` — промпт под выбранный отрезок; `window_text` —
    «30 мин» / «12 ч». В промпте никогда не советовать разгон.
- `analyzer/web/`:
  - `server.py` — локальный сервер (127.0.0.1, проверка Host, POST только с заголовком
    `X-App-Request`, CSP, тело до 10 КБ). GET `/`, `/api/state`; POST `ask`, `clear`,
    `setting`, `key`, `window`, `open`, `hide_hint`. `settings_fields()` — поля окна
    «Настройки» (ключ наружу не отдаётся, только «есть он или нет»).
  - `static/index.html` — весь UI в одном файле, опрос каждые 2 с, перерисовка
    откладывается, пока фокус в INPUT. Чипы «Показывать за», блок вопроса, нагрузка,
    температуры, питание, «кто берёт сейчас», журнал, окно «Настройки» и поле ключа.

## Решения владельца (26.10.2026)

- Отдельный проект, не часть AITG. Свой `run.bat`, окно в браузере/Edge.
- Без Telegram, без LM Studio, без режимов. Только показ в окне приложения.
- ИИ — Gemini. Поле «ключ Gemini» в настройках, ключ только локально (`data/secrets.json`,
  в `.gitignore`), не логировать. Модель по умолчанию `gemini-flash-latest`, имя меняется
  в настройках. Без ключа работает всё, кроме текстового разбора.
- Хранение журнала: по умолчанию 12 часов, меняется в интерфейсе.
- Температура CPU через LibreHardwareMonitor — оставить (опционально). При первом запуске,
  если программа не найдена, показать подсказку и открыть на ПК страницу загрузки на GitHub.
- Отчётов картинкой и Telegram не нужно.
- Тесты как в AITG, зависимости минимум.
- GitHub: 26.10 владелец попросил выложить отдельным публичным проектом.

## Безопасность

- Окно: только 127.0.0.1, проверка Host, POST только с `X-App-Request`, CSP, тело до 10 КБ.
- Ключ Gemini — в `data/secrets.json`, в заголовке запроса (не в адресе), никогда не печатать,
  не логировать, не коммитить и не отдавать в окно. В сообщениях об ошибке Gemini ключ вырезается.
- `data/` (ключ, журнал нагрузки, состояние, логи) — личное, не коммитить.
